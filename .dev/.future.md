 # Plan: Exchange-Style View Layer for MarketEngine with UI-Derived Pays out x and Template-Level Yield Snapshots

  ## Summary

  Extend the current minimal read surface in IMarketEngine / MarketEngineViewModule into a higher-level view layer
  with two explicit consumers:

  - Prediction-market views for frontend/trader UX
  - Operator views for pause, router-failure, recovery, and rolling-lifecycle monitoring

  The implementation should stay hybrid:

  - on-chain is the canonical source of current state only
  - off-chain indexer/UI derives historical charts and presentation-only metrics

  Locked product semantics:

  - Pays out x is UI-derived from current pool-implied probability only
  - template Yield % is a current non-annualized yield ratio
  - yield is exposed at template scope, not as a primary epoch metric

  This fits the current codebase and currentSmartContract.md: the engine already stores enough for current epoch,
  position, recovery, and router-state snapshots, but it does not store historical probability series and the router’s
  live value is template-scoped, not epoch-scoped.

  ## Key Changes

  ### 1. Replace the minimal view surface with grouped snapshot getters

  Keep existing low-level getters unchanged for compatibility:

  - getUserEpochs
  - getVaultBalances
  - getRollingLifecycle
  - getEpoch
  - unreconciledRecoveredByTemplate

  Add new high-signal read methods to IMarketEngine, implemented in MarketEngineViewModule and wired through
  dispatcher selectors:

  - getMarketView(bytes32 templateId) returns (MarketView memory)
  - getEpochView(bytes32 templateId, uint64 epochId) returns (EpochView memory)
  - getActiveEpochView(bytes32 templateId) returns (EpochView memory)
  - getOutcomeViews(bytes32 templateId, uint64 epochId) returns (OutcomeView[] memory)
  - getPositionView(bytes32 templateId, uint64 epochId, address user) returns (PositionView memory)
  - getTemplateYieldView(bytes32 templateId) returns (TemplateYieldView memory)
  - getOperatorTemplateView(bytes32 templateId) returns (OperatorTemplateView memory)
  - getOperatorGlobalView() returns (OperatorGlobalView memory)

  Optional convenience method if selector budget and complexity stay reasonable:

  - getUserEpochPositionViews(bytes32 templateId, address user, uint256 cursor, uint256 size)

  ### 2. Add explicit view structs in IMarketEngine

  Use typed snapshot structs instead of large tuple returns.

  Recommended structs:

  - MarketView
      - template metadata needed by UI: templateId, slug, assetSymbol, marketType, executionMode
      - outcomeCount, active, activeEpochId
      - globalPaused
      - template/ledger health flags: rolling phase, halt reason, template user-ops blocked
      - fee fields relevant to UI: switchFeeBps, settlementFeeBps
      - oracle routing metadata: templateOracleKind, oracleClass, eventOracle
      - yield routing flag: whether a router is configured
  - EpochView
      - epochId, status, cancelReason
      - openAt, lockAt, resolveAt, createdAt, lockedAt, resolvedAt
      - totalPool, totalPositions
      - claimable, refundMode
      - settlement/accounting fields: winningOutcomeMask, claimLiabilityTotal, totalRefundLiability,
        settlementFeeTotal, claimedTotal, remainingWinningStake
      - routedPrincipal
      - checkpoint summary: checkpointA, checkpointB, optional B-side/composite presence flags as needed for UI
      - effective oracle limits used by this epoch
  - OutcomeView
      - outcomeIndex
      - poolSize
      - impliedProbabilityE6
      - displayPercentE4
      - isWinner
      - isActiveQuote
      - grossPayoutXE6
  - PositionView
      - initialized, claimed
      - stakes
      - totalStake
      - entryFeesPaid, switchFeesPaid
      - claimedAmount
      - claimableNow
      - pendingClaimAmount
      - pendingRefundAmount
      - winningStake
      - positionStatus as an enum or compact code: no position / open / settled-unclaimable / claimable / claimed
  - TemplateYieldView
      - routerAssigned
      - routerDisabled
      - recoveryPending
      - yieldPath
      - currentPrincipal
      - currentValue
      - unrealizedYieldAmount
      - yieldRatioE6
      - scaledPrincipal
      - stataShares
      - yieldFeeBpsCurrent
  - OperatorTemplateView
      - activeEpochId, lastResolvedEpochId, haltedAtEpochId, rollingNextEpochId
      - rollingPhase, rollingHaltReason
      - vault balances: activeVault, claimsVault, feesVault
      - templateRoutedPrincipal
      - unreconciledRecoveredAmount
      - userOpsBlocked
      - unsafeToUnpauseForTemplate
  - OperatorGlobalView
      - globalPaused
      - yieldRouter
      - yieldRouterDisabled
      - yieldRouterFailureCount
      - totalRoutedPrincipal
      - totalUnreconciledRecovered
      - admin, treasury, workerAuthority
      - configured oracle adapter addresses if useful for ops

  ## View Semantics

  ### 3. Prediction-market pricing and Pays out x

  Use only current canonical epoch state.

  For open or locked epochs:

  - implied probability per outcome = outcomePools[i] / totalPool
  - expose normalized probabilities in fixed precision for UI, plus raw pools
  - if totalPool == 0, return zero probabilities and zero multiplier

  For settled/cancelled/voided epochs:

  - do not present live quote semantics
  - OutcomeView.isWinner should reflect winningOutcomeMask
  - OutcomeView.isActiveQuote should be false

  Pays out x policy:

  - contract does not expose a single “truth” multiplier field as protocol logic
  - contract may expose grossPayoutXE6 as a convenience field only if defined explicitly as a UI helper derived from
    current probability, not an accounting primitive
  - canonical formula:
      - if active and outcomePools[i] > 0, grossPayoutX = totalPool / outcomePools[i]
      - equivalent to reciprocal of pool-implied probability
  - no settlement-fee deduction is baked into this number
  - frontend may separately label it as approximate/implied

  This avoids falsely presenting pooled-share state as an orderbook quote while still enabling Kalshi-style UX.

  ### 4. Position and claim-preview semantics

  PositionView should be derived from existing storage:

  - epoch from _epochs[templateId][epochId]
  - position from _positions[positionKey(templateId, epochId)][user]

  Preview rules must reuse the same math path as claims:

  - if e.claimable == false, preview amounts are zero
  - if e.refundMode == true, pendingRefundAmount = pos.totalStake
  - otherwise compute preview with the same logic as _claimOne:
      - remainingClaims = e.claimLiabilityTotal - e.claimedTotal
      - use MarketMath.computeClaimPayoutStorage semantics
  - last-claimer remainder behavior must be preserved in the preview because it is part of real payout logic
  - pendingClaimAmount and winningStake should be zero for users without winning stake

  Do not attempt on-chain trade history, average entry price, fills, or time-weighted exposure. Current storage does
  not support it cleanly and that belongs off-chain.

  ### 5. Yield snapshot semantics

  Yield is template-scoped.

  TemplateYieldView should be sourced from current router reads when a router is configured:

  - currentValueOf(templateId)
  - principalOf(templateId)
  - scaledPrincipalOf(templateId)
  - stataSharesOf(templateId)
  - getTemplateYieldPath(templateId)

  Calculation rules:

  - if no router: zeroed view, routerAssigned = false
  - unrealizedYieldAmount = max(currentValue - currentPrincipal, 0)
  - yieldRatioE6 = unrealizedYieldAmount / currentPrincipal in fixed precision when principal > 0, else zero
  - do not annualize on-chain
  - do not compute APR/APY in-contract
  - expose degraded-state flags:
      - routerDisabled = yieldRouterDisabled
      - recoveryPending = (_unreconciledRecoveredByTemplate[templateId] != 0)
  - include yieldFeeBpsCurrent = yieldFeeBps

  Important boundary:

  - this view is for current routed state, not per-epoch settled yield attribution
  - _epochYieldFeeBps and EpochYieldAccrued remain accounting/event history primitives, not the primary PM-facing
    yield display

  ### 6. Operator-state semantics

  Operator views must surface the recovery and pause model already enforced by admin/security logic.

  OperatorTemplateView should directly represent:

  - rolling state from _ledgers[templateId]
  - vault state from _vaults[templateId]
  - unreconciled recovery from _unreconciledRecoveredByTemplate[templateId]
  - routed principal from _templateRoutedPrincipal[templateId]
  - user-ops blocked when:
      - protocol is globally paused, or
      - rolling template is halted and user ops are blocked by current lifecycle rules
  - unsafe/unhealthy template when any of:
      - unreconciled recovery pending
      - router disabled with template routed principal still outstanding

  OperatorGlobalView should directly represent:

  - globalPaused
  - router address and disabled state
  - failure count
  - total routed principal
  - total unreconciled recovered
  - admin/treasury/worker addresses

  Do not embed policy beyond current code behavior. The view layer should expose state, not invent new incident logic.

  ## Implementation Notes

  - Implement all new functions in MarketEngineViewModule only.
  - Append new structs and function signatures to IMarketEngine; do not change existing function signatures.
  - Preserve dispatcher architecture: add selector wiring only, no lifecycle/accounting mutations.
  - Read directly from:
      - _templates
      - _ledgers
      - _vaults
      - _epochs
      - _positions
      - _templateRoutedPrincipal
      - _unreconciledRecoveredByTemplate
      - public router/global state already in MarketEngineState
  - For active epoch lookup, use ledger.activeEpochId; if zero or missing, return a zero/default EpochView only if
    that is consistent with existing product expectations, otherwise revert InvalidEpochState.
  - Use bounded iteration up to epoch.outcomeCount; never semantically expose the full fixed array length of 8 as
    active outcomes.

  ## Off-Chain Responsibilities

  Keep historical and presentation-derived data off-chain:

  - historical per-outcome percentage charts
  - chart candles and time-bucket policies
  - APR/APY or time-window yield metrics
  - trade/fill reconstruction
  - average entry price
  - richer activity feeds

  Indexer sources:

  - PositionDeposited
  - SideSwitched
  - EpochOpened
  - EpochLocked / EpochLockedV2
  - EpochResolved / EpochResolvedV2
  - EpochCancelled
  - rolling lifecycle and yield/recovery events
  - optional polling of the new view getters for chart snapshots

  ## Test Plan

  Add contract tests covering:

  - getMarketView
      - manual and rolling templates
      - paused protocol
      - halted rolling lifecycle
      - correct template metadata and fee fields
  - getEpochView
      - open, locked, resolved, cancelled, voided/refund-mode epochs
      - correct accounting fields and checkpoint summaries
      - correct routed-principal visibility
  - getOutcomeViews
      - 2-outcome and multi-outcome markets
      - zero-pool epoch returns zero probabilities and zero grossPayoutX
      - settled epoch marks winners and disables active-quote semantics
      - probabilities sum to fixed-point total within bounded rounding drift
  - getPositionView
      - user with no position
      - user with live open position
      - resolved winning position
      - resolved losing position
      - refund-mode epoch
      - already claimed position
      - no router configured
      - principal == current value
      - positive unrealized yield
      - router disabled state
      - unreconciled recovery pending
      - path reporting for AToken vs Stata path
  - getOperatorTemplateView / getOperatorGlobalView
      - global paused state
      - router disabled / failure-count state
      - unreconciled recovery state
      - rolling halted state
      - outstanding routed principal state
      - unsafe-to-unpause relevant flags

  ## Assumptions

  - Pays out x is intentionally a pool-implied UI metric, not a settlement guarantee and not an orderbook quote.
  - Template Yield % means current unrealized yield ratio, not APR/APY.
  - Yield display is template-scoped because current router value is template-scoped in the existing router surface.
  - No on-chain historical chart persistence is added in this phase.
  - No new storage is required for the view layer unless a future iteration explicitly decides to cache convenience
    fields.
