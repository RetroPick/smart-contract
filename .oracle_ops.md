## Oracle Classes in Production

The engine supports multiple oracle adapter classes:

- rate oracle
- smart data oracle
- macro oracle
- equity oracle
- trusted reporter oracle

Each production template must have an explicitly approved oracle source.

## Oracle Operations Principles

1. Oracle choice is part of market design, not an afterthought.
2. Replacing an oracle is a governance event.
3. Active-epoch settlement assumptions must not be changed casually.
4. Trusted-reporter markets are operationally heavier than standard adapter markets.

## Chainlink-Family Oracle Operations

### Before Enabling a Feed

Operators must verify:

- feed contract address
- decimals configuration
- update heartbeat expectations
- acceptable staleness window
- acceptable confidence policy for the market
- sequencer uptime feed requirements for the chain

### Required Per-Market Oracle Matrix

Maintain an internal oracle matrix containing:

- template id / slug
- oracle class
- feed ids
- adapter address
- feed decimals configured
- expected heartbeat
- `oracleMaxDelaySeconds`
- confidence assumptions
- fallback/incident plan

No market should go live unless it appears in the approved oracle matrix.

### Oracle Replacement

When replacing an adapter:

1. pause protocol
2. identify all affected templates
3. evaluate whether already-open epochs must continue under prior snapshot semantics
4. execute adapter replacement through admin governance
5. reset oracle cursor only if needed and allowed
6. validate active and next epoch behavior

### Cursor Reset Rules

`resetOracleCursor(templateId, feedId)` is a sensitive operation.

Hard rules:

- only after admin review
- only for the specific template/feed pair that needs reset
- never while the active epoch is `Open` or `Locked`
- never as a broad “cleanup” operation

## Oracle Monitoring

Operators must monitor:

- oracle adapter replacement events
- cursor reset events
- stale-oracle related failures in worker operations
- rolling halts caused by oracle issues
- unexpected settlement-source changes

High-severity alerts:

- any oracle adapter replacement
- any oracle cursor reset
- repeated oracle-related lock/resolve failures

## Trusted Reporter Operations

Trusted reporter is a strong centralization point. Treat it like production signing infrastructure.

### Required Roles

- Admin Safe owns the adapter
- reporter key signs lock/resolve/OHLC payloads
- oracle ops team manages reporter process

### Reporter Key Requirements

- dedicated key only
- isolated device or service
- strict access control
- audit log of signing activity
- no reuse as admin or treasury signer

### Trusted Reporter Bring-Up Checklist

Before enabling reporter markets:

1. verify adapter ownership is Admin Safe
2. verify `trustedReporter`
3. verify `maxSignatureAgeSeconds`
4. test posting flow in non-production environment
5. confirm correction process with operators
6. confirm monitoring of clear events

### Trusted Reporter Corrections

Correction functions:

- `clearLockSample`
- `clearResolveResult`
- `clearOhlcResult`

Correction policy:

- every clear must have an internal incident or correction record
- every clear must be followed by verification of emitted event
- only the minimal necessary clear action should be used
- corrected payload must be reposted only after human review

### Reporter Rotation

`setTrustedReporter(newReporter)` is a security event.

Use it for:

- key compromise
- key retirement
- infrastructure migration

Required procedure:

1. create governance ticket
2. pause engine if live markets could be impacted
3. rotate reporter through Admin Safe
4. verify `TrustedReporterUpdated`
5. confirm downstream systems are aware that `reporterEpoch` changed

### Reporter Compromise Procedure

If reporter compromise is suspected:

1. pause affected reporter-settled markets immediately
2. stop trusting all outstanding unpublished or unverified reporter payloads
3. rotate reporter key
4. inspect markets for incorrect lock/resolve/OHLC posts
5. use clear functions where needed
6. record full incident timeline

## Trusted Reporter Observability

Monitor at minimum:

- `TrustedReporterUpdated`
- `LockSampleCleared`
- `ResolveResultCleared`
- `OhlcResultCleared`

Treat every such event as high-severity production telemetry.

## Oracle Change Approval Standard

Before any oracle or reporter change, operators must document:

- why the change is needed
- which templates are affected
- whether pause is required
- whether cursor reset is required
- what the post-change settlement assumptions are

## Final Policy Statement

Oracle operations are part of settlement integrity.

A market with weak oracle operations is not a safe market, even if the on-chain code is correct.
