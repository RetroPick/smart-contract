# RetroPick V1 Market-Type Operator Guide

## Purpose

This document is the operator-facing approval guide for the current consolidated market-type set.

It answers:

- which market families are suitable for guarded production
- which are rolling-compatible
- which require extra oracle or incident handling
- what must be reviewed before a template goes live

## Canonical Market Types

The current canonical set is:

1. `Direction`
2. `Threshold`
3. `RangeClose`
4. `Velocity`
5. `Ladder`
6. `Convergence`
7. `Composite`
8. `Corridor`
9. `Cascade`

Threshold-like legacy business cases should still route through `Threshold` plus `oracleClass` and template metadata.

## Operational Compatibility Guide

### Lowest operator burden

Best initial guarded-MVP candidates:

- `Direction`
- `Threshold`
- `RangeClose`

These should be the default first-launch families.

### Medium operator burden

Use only after the team is comfortable with baseline operations:

- `Velocity`
- `Ladder`

These add more nuanced settlement behavior and should be template-reviewed carefully.

### High operator burden

Use only with explicit approval and a written incident plan:

- `Convergence`
- `Composite`
- `Corridor`
- `Cascade`

These involve multi-feed, path-dependent, or more complex settlement semantics.

## Rolling Compatibility

Operationally:

- rolling-compatible families may be used only when they pass current validation and the team is confident in rolling ops
- manual-only or operationally complex families should remain manual unless there is a strong reason otherwise

Base policy for guarded MVP:

- start with manual templates first
- enable rolling only for explicitly approved low-complexity templates
- do not mix a new market family with rolling as the first launch path

## Oracle-Class Selection

Each template must have an explicitly approved oracle class and data source.

Operator review must confirm:

- correct oracle family
- correct feed ids
- correct adapter address
- correct delay/confidence settings
- whether a reporter path is involved

## Template Approval Checklist

Before any template goes live:

1. confirm the market family is allowed by launch policy
2. confirm the oracle class and feeds are approved
3. confirm whether the market is manual or rolling
4. confirm the market has a documented incident plan
5. confirm whether yield routing is enabled or intentionally disabled
6. confirm whether multi-side positions are intentionally allowed
7. confirm the market’s TVL cap and launch tier

## Market-Family Notes

### Direction

- best default for simple directional markets
- low operator complexity

### Threshold

- default family for fixed-level binary questions
- includes former domain-specific threshold variants through metadata

### RangeClose

- suitable when bucketed close-price outcomes are needed
- operator complexity remains moderate if oracle source is simple

### Velocity

- requires careful review of bounds and settlement interpretation

### Ladder

- requires careful review of ladder bounds and payout weights
- operators should verify economic intent, not just code validity

### Convergence

- dual-feed behavior increases oracle ops burden
- must have a clear incident path for one-feed or spread-quality issues

### Composite

- multi-feed logic increases review burden
- operators must understand the exact logical aggregation before launch

### Corridor

- path-dependent semantics increase settlement review burden
- do not launch casually without explicit operator familiarity

### Cascade

- level-break semantics and directional interpretation increase review burden
- require explicit human review before every production introduction

## Launch Tiers

Recommended internal launch tiers:

- Tier 1:
  - `Direction`
  - `Threshold`
  - `RangeClose`
- Tier 2:
  - `Velocity`
  - `Ladder`
- Tier 3:
  - `Convergence`
  - `Composite`
  - `Corridor`
  - `Cascade`

Tier 3 should require stronger review and explicit approval from protocol engineering and operations.

## Final Policy

Market-type approval is not just “does the code support it.”

It is “can the operator team safely deploy, monitor, halt, explain, and recover it under real production conditions.”
