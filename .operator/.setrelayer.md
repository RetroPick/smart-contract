# Gasless faucet relayer setup (Base Sepolia)

## Purpose

This tutorial configures the **RetroPick Go API** to relay `TokenFaucet.requestWithSig` on **Base Sepolia (`84532`)** so users can claim demo stake **without paying gas** from their own EOA. Gas is paid by a **dedicated relayer hot wallet** controlled via environment variables.

- **No smart contract redeploy** is required if the deployed `TokenFaucet` already implements `requestWithSig` (see [../.docs/faucet/README.md](../.docs/faucet/README.md)).
- Relay logic lives in **`apps/backend`** (not in this Solidity package); this doc is the operator-facing checklist.

## Prerequisites

1. **`TokenFaucet` deployed** and `tokenFaucet` (and `stakeToken`) consistent with the API’s embedded registry, e.g. [`../../apps/backend/internal/registrydata/registry.json`](../../apps/backend/internal/registrydata/registry.json).
2. **Go API** can run with valid `DATABASE_URL` and JSON-RPC access to Base Sepolia (`RPC_URL`).
3. A **dedicated** secp256k1 private key (**32 bytes**, 64 hex characters) used **only** for faucet relay — do not reuse production/mainnet admin keys.

## 1. Create and fund the relayer EOA

1. Generate or import a key and record the **relayer address** (example with Foundry):

   ```bash
   cast wallet address --private-key 0x<YOUR_64_HEX_CHARS>
   ```

2. Fund that address with **Base Sepolia ETH** (native gas on chain `84532`). This is **not** Ethereum Sepolia (`11155111`) ETH.

   Examples of public faucets (availability changes over time):

   - [Coinbase Base Sepolia faucet](https://portal.cdp.coinbase.com/products/faucet?token=ETH&network=base-sepolia)
   - [Alchemy Base Sepolia faucet](https://www.alchemy.com/faucets/base-sepolia)

3. **Monitor balance** on [Basescan Sepolia](https://sepolia.basescan.org/) (or your explorer). Low or zero balance causes relay transactions to fail with insufficient funds.

## 2. Configure the API environment

Set these variables on the **API** host (see monorepo root [`.env.example`](../../.env.example)).

| Variable | Required | Description |
|----------|----------|-------------|
| `FAUCET_RELAY_ENABLED` | Yes | Must be exactly `1` to turn relay on. |
| `FAUCET_RELAYER_PRIVATE_KEY` | Yes | Hex private key (with or without `0x` prefix). If empty or relay flag not `1`, relay stays disabled. |
| `RPC_URL` | Recommended | Base Sepolia JSON-RPC. The API defaults to a public endpoint if unset; production should use a reliable provider. |
| `FAUCET_RELAY_DEADLINE_MAX` | No | Maximum allowed skew for EIP-712 `deadline` vs server clock (Go duration, e.g. `15m`). Default in code is 15 minutes. |

Relay is active only when **`FAUCET_RELAY_ENABLED=1` and the private key is non-empty**.

On successful startup with relay enabled, the API logs the **relayer address** (JSON log field from `cmd/api`).

## 3. Verification

1. **`GET /api/v1/livez`** — response should include `"faucetRelayEnabled": true` when relay is configured.
2. **`GET /api/v1/config/contracts`** — merged payload includes `faucetRelayEnabled` for the frontend.
3. **Frontend** (`apps/fe-v1`) must use the **same API base URL** (`NEXT_PUBLIC_API_URL` or `VITE_API_URL`) so `fetchRegistryContracts` sees `faucetRelayEnabled` and the portfolio/fund-wallet flows offer the gasless path.

### Relay endpoint (reference)

- **`POST /api/v1/user/faucet-relay`**
- JSON body: `recipient`, `amount` (decimal string), `deadline` (unix seconds), `signature` (`0x…`, 65-byte ECDSA).

The server enforces **`amount` equal to on-chain `maxMintAmount`**, validates EIP-712 against `TokenFaucet` + current `nonces(recipient)`, simulates the call, then submits the transaction from the relayer EOA. End-to-end testing is easiest via the app (wallet signs typed data); low-level `curl` requires a valid signature.

## 4. Security and abuse

- **Secrets:** inject `FAUCET_RELAYER_PRIVATE_KEY` via your platform’s secret store; never commit it; use a **different** key per environment; rotate if leaked.
- **Rate limiting:** the API applies a **per-IP** limiter on `POST /api/v1/user/faucet-relay`. For a public internet deployment, add stronger controls (e.g. CAPTCHA, allowlists, or authenticated beta).
- **On-chain limits:** cooldown and nonce semantics still apply inside `TokenFaucet`; relay does not bypass `lastMintAt` / caps.

## 5. Troubleshooting

| Symptom | Likely cause |
|---------|----------------|
| HTTP **501** / JSON `faucet relay not enabled` | `FAUCET_RELAY_ENABLED` not `1`, or private key missing/empty. |
| `invalid signature` / simulation revert | Wrong nonce, `amount` not exactly `maxMintAmount`, expired `deadline`, clock skew, or wallet signed on wrong `chainId` / wrong `verifyingContract`. |
| RPC / send errors, “insufficient funds” | Relayer EOA needs more Base Sepolia ETH. |
| Frontend never offers gasless claim | API not exposing `faucetRelayEnabled: true`, or browser pointing at a different API URL. |
