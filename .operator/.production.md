# RetroPick V1 Production Guide

## Purpose

This is the authoritative operator guide for deploying and maintaining RetroPick V1 on **Base mainnet** under the current V2 architecture.

- custody and signer topology
- deployment sequencing
- post-deploy validation
- guarded-MVP launch policy
- upgrade and module governance
- router, oracle, and reporter operational boundaries

## Production Positioning

RetroPick V1 should be operated as a **guarded MVP beta**, not as unrestricted high-TVL infrastructure.

Production assumptions:

- governance is trusted and competent
- privileged actions are multisig-controlled
- stake token is a standard ERC20 only
- market creation is admin-controlled only
- yield routing is optional and may be disabled by default
- safe operation depends on ops discipline as much as code correctness

Do not describe the protocol internally or externally as trustless.

## Architecture Summary

### V2 Dispatcher Boundary

The current production architecture is **hybrid**, not “everything delegated.”

Root-owned on `MarketEngineDispatcher`:

- upgrades
- module governance primitives
- direct admin functions
- direct user and claims functions

Delegated through selector routing only:

- core manual lifecycle
- rolling lifecycle
- view functions

Operational consequence:

- selector manifests must distinguish **root-owned selectors** from **delegated selectors**
- only delegated selectors should ever be wired through `setSelectorModule`
- any runbook or script that assumes admin/user selectors are delegated is stale and unsafe

### Main Trust Boundaries

The real production trust boundaries are:

- `admin` multisig
- UUPS upgrade authority
- module bytecode allowlisting and registration
- delegated selector routing
- router governance
- oracle adapter governance
- trusted reporter governance
- worker key operations

If the admin Safe is compromised, protocol integrity is compromised.

## Recommended Account Topology

### 1. Admin Safe

Use this Safe for:

- upgrades
- module allowlisting and registration
- delegated selector routing
- pause and unpause
- router, oracle, worker, and treasury changes
- emergency recovery actions

Recommended threshold:

- guarded launch: `2-of-3` only if signer quality is high
- preferred Base mainnet production MVP: `3-of-5`

Hard requirements:

- hardware wallets only
- no hot-browser-only signers
- written owner roster
- written incident escalation tree

### 2. Treasury Safe

Use a separate Safe for fee custody.

It should:

- receive fee withdrawals
- not hold upgrade authority
- not be the same Safe as `admin` unless there is a documented temporary exception

### 3. Worker Authority

Use a dedicated operational EOA or managed keeper key for:

- manual lifecycle execution
- rolling lifecycle execution
- LM reward claim operations

It must not control:

- upgrades
- treasury
- module governance
- router governance
- oracle governance

### 4. Trusted Reporter Key

If reporter-settled markets are enabled:

- reporter key must be isolated from admin and treasury keys
- reporter key must be treated as settlement-critical infrastructure
- adapter ownership should remain with the Admin Safe

## Base Mainnet Deployment Assumptions

Operators should assume:

- Chainlink L2 sequencer feed behavior matters for Base
- stale feed and confidence-wide failures can halt or block lifecycle work
- router health should be treated as a first-class production dependency if yield routing is enabled

Base-mainnet-specific preconditions:

1. Verify intended sequencer feed configuration in the adapter deployment.
2. Verify all Chainlink-family adapters used by production templates are the approved Base addresses.
3. Verify the stake token is the exact approved Base deployment and behaves as a standard ERC20.
4. Verify any Aave/yield dependencies match the approved Base deployment set.

## Deployment Model

### Required Artifacts Per Deployment

For every environment, maintain a release record containing:

- chain id and environment name
- proxy address
- dispatcher implementation address
- admin Safe address
- treasury Safe address
- worker address
- oracle adapter addresses
- yield router address, if any
- trusted reporter adapter address, if any
- deployed module addresses
- approved module code hashes
- delegated selector manifest
- deployment and verification transaction hashes

### Required Post-Deploy Validation

Before first deposit:

1. Verify proxy and implementation addresses.
2. Verify initialization config:
   - stake token
   - base oracle
   - admin
   - treasury
   - worker
   - default settlement fee
   - max switch fee
   - max outcomes
   - global oracle config
3. Verify module code hashes and registrations.
4. Verify delegated selector wiring against `ScriptSelectorMatrix`.
5. Verify root-owned admin/user selectors are not treated as delegated in manifests or scripts.
6. Verify oracle family adapter addresses.
7. Verify the yield router is either intentionally unset or matches the approved deployment.
8. Verify monitoring and alerting are live before deposits are accepted.

## Guarded-MVP Launch Policy

Default launch controls:

- hard global TVL cap
- per-template TVL cap
- standard ERC20 stake token only
- admin-only template creation and market initialization
- yield router off by default, or enabled only for a small allowlist
- trusted-reporter markets off unless explicitly approved
- no high-complexity market families without a written incident plan

Recommended initial Base launch profile:

- start with manual markets first
- keep rolling markets limited to approved templates
- keep yield routing either disabled or enabled for one low-cap template
- keep reporter-settled markets disabled until separate operator drills are complete

## Unpause Safety Standard

Unpause is not a cosmetic action. It is a state-integrity decision.

Do not unpause unless:

- `totalUnreconciledRecovered == 0`
- `yieldRouterDisabled == false` if routing is expected in production
- no template has unresolved recovery pending
- no template is unsafe to unpause according to operator views
- incident commander and technical reviewer both sign off

If any template still shows degraded recovery or disabled-router-with-routed-principal state, keep the protocol paused.

## Production Anti-Patterns

Do not:

- treat all selectors as delegated
- sign delegated selector rewires for root-owned selectors
- replace the yield router while routed principal is outstanding
- unpause through uncertainty
- combine upgrade, router replacement, and oracle replacement in one window
- use an unsupported or fee-on-transfer stake token
- rely on stale docs over live on-chain state and current scripts

## Final Policy

Base mainnet operation should follow a single rule:

**when code truth, script truth, and operator understanding diverge, stop and reconcile before taking action.**
