# RetroPick V1 Operator Runbook

## Purpose

This is the day-to-day and incident-response runbook for operating the current V2 `MarketEngine`.

Primary contract surfaces:

- [../src/engine/MarketEngineDispatcher.sol](../src/engine/MarketEngineDispatcher.sol)
- [../src/engine/modules/MarketEngineAdminModule.sol](../src/engine/modules/MarketEngineAdminModule.sol)
- [../src/engine/modules/MarketEngineCoreLifecycleModule.sol](../src/engine/modules/MarketEngineCoreLifecycleModule.sol)
- [../src/engine/modules/MarketEngineRollingLifecycleModule.sol](../src/engine/modules/MarketEngineRollingLifecycleModule.sol)
- [../src/engine/modules/MarketEngineViewModule.sol](../src/engine/modules/MarketEngineViewModule.sol)

Use this document as the operational source of truth after deployment.

## Operator Truth Sources

Read state in this order:

1. dedicated V2 operator/view getters
2. direct contract state
3. events
4. deployment manifests and Safe records

Preferred read surfaces:

- `getOperatorGlobalView()`
- `getOperatorTemplateView(templateId)`
- `getEpochView(templateId, epochId)`
- `getTemplateYieldView(templateId)`
- `getPositionView(templateId, epochId, user)` when investigating claimability

Do not infer live state from old selector assumptions, stale docs, or historical deployment notes.

## Core Operating Rules

### Default to fail closed

When there is uncertainty:

- pause first
- preserve evidence
- stop new routing and new ops
- recover only through documented flows

### Never improvise on live state

Do not perform any privileged state-changing action without:

- the intended state transition
- the expected resulting checks
- a rollback or containment path

### Separate maintenance windows

Do not combine:

- upgrades
- router changes
- delegated module changes
- oracle adapter changes

Each is its own change unless the release plan explicitly requires coupling.

## Daily Checks

At least once per day, and before active market windows:

1. Read `getOperatorGlobalView()` and confirm:
   - `globalPaused` is expected
   - `yieldRouterDisabled` is false unless incident handling is active
   - `totalUnreconciledRecovered == 0`
   - `admin`, `treasury`, and `workerAuthority` match the approved record
2. For each active template, read `getOperatorTemplateView(templateId)` and confirm:
   - `userOpsBlocked` is expected
   - `unreconciledRecoveredAmount == 0`
   - `unsafeToUnpauseForTemplate == false`
   - rolling phase and halt reason are expected
3. If yield routing is enabled for a template, read `getTemplateYieldView(templateId)` and confirm:
   - `routerAssigned == true`
   - `routerDisabled == false`
   - `recoveryPending == false`
4. Confirm no unexpected upgrade, module, selector, router, oracle, or reporter events occurred.

## Pre-Market-Window Checks

Before opening or operating active markets:

1. Confirm protocol is not paused.
2. Confirm no recovery state is pending globally or on relevant templates.
3. Confirm oracle adapters are the approved ones for the target templates.
4. Confirm worker key is funded and healthy.
5. Confirm rolling templates are not halted unless intentionally under recovery.
6. Confirm any reporter-backed market has healthy reporter infrastructure and no unresolved clear/correction event.

## Manual Market Operations

### Open Epoch

Preconditions:

- protocol not paused
- template initialized and active
- no unreconciled recovery for the template
- for rolling templates, do not use manual open while live rolling is active

Validation after open:

- `activeEpochId` updated in `getOperatorTemplateView`
- `getEpochView` shows expected open/lock/resolve timing
- market is not accidentally blocked for user ops

### Lock Epoch

Preconditions:

- protocol not paused
- epoch is active and lockable
- oracle source is healthy

Stop conditions:

- stale oracle
- confidence-wide oracle
- unexpected adapter mismatch

Validation after lock:

- `checkpointA` present when expected
- status is `Locked`
- no unintended halt or recovery state introduced

### Resolve Epoch

Preconditions:

- protocol not paused
- epoch is resolvable
- no unreconciled recovery pending
- if routing is enabled, router is healthy enough for principal withdrawal

Validation after resolve:

- `claimable == true`
- `claimLiabilityTotal`, `settlementFeeTotal`, and `claimedTotal` look sane
- if refund mode: claims remain local
- if settled-claim routing is enabled: verify via `getEpochView` that routed settled claims state is expected

## Rolling Market Operations

### Genesis Start

Preconditions:

- template is configured for rolling mode
- `rollingPhase == Uninitialized`
- no unresolved recovery state

Validation:

- `rollingPhase == GenesisOpen`
- `rollingNextEpochId` advanced as expected
- epoch timings match the approved interval

### Genesis Lock

Preconditions:

- `rollingPhase == GenesisOpen`
- lock window is within buffer
- oracle sample is healthy

Validation:

- `rollingPhase == Live`
- current and next epoch linkage is sane
- no halt reason set

### Execute Rolling Round

Preconditions:

- `rollingPhase == Live`
- resolve and lock windows are still inside buffers
- no unreconciled recovery pending
- if routing is enabled, no disabled-router state blocks lifecycle

If execution halts:

- read `rollingHaltReason`
- determine whether the cause is:
  - buffer miss
  - oracle failure
  - confidence-wide oracle
  - router/recovery failure

Do not keep retrying blindly once halted. Switch to incident handling.

## Pause and Unpause

### Pause

Pause immediately for:

- router failure uncertainty
- recovery pending state
- settlement-source uncertainty
- unexpected module or upgrade event
- reporter compromise or correction uncertainty
- governance key compromise suspicion

After pause:

1. capture current operator views
2. capture relevant recent events
3. identify affected templates and epochs
4. choose either recovery, rollback, or postmortem path

### Unpause

Unpause only after all are true:

- `totalUnreconciledRecovered == 0`
- `yieldRouterDisabled == false` if routing is intended
- each affected template has `unsafeToUnpauseForTemplate == false`
- rolling templates are either healthy or intentionally kept halted
- incident commander and technical reviewer both approve

## Yield Router Recovery

### Emergency Withdraw

Use `yieldEmergencyWithdraw(templateId)` only when:

- protocol is paused
- template is valid
- recovery is necessary due to router failure or integrity uncertainty

Validate after emergency withdraw:

- `YieldEmergencyWithdrawn` emitted
- `_unreconciledRecoveredByTemplate` increased
- `totalUnreconciledRecovered` increased

### Reconcile Active Routed Principal

Use `reconcileEpochRoutedPrincipal(templateId, epochId, recoveredPrincipal)` only when:

- protocol is paused
- recovered amount is present in the template recovery bucket
- the epoch routed principal is the intended target

Validate after reconcile:

- epoch routed principal decreased
- template and global routed principal decreased
- unreconciled recovered decreased

### Recover Routed Settled Claims

Use `recoverRoutedSettledClaims(templateId, epochId, recoveredAmount)` only when:

- protocol is paused
- the epoch has routed settled claims enabled
- recovered funds are already in the template recovery bucket

Validate after recovery:

- routed settled-claims bucket is disabled
- claims vault increased
- `claimLiabilityTotal` now reflects local claimability
- global routed principal decreased accordingly

### Finalize Excess Recovered Yield

Use `finalizeRecoveredYield(templateId)` only when:

- protocol is paused
- `totalRoutedPrincipal == 0`
- only excess recovered value remains

Validate after finalize:

- unreconciled recovered for the template is zero
- excess was moved into fee reserves

## Oracle and Reporter Operations

Use [./.oracle_ops.md](./.oracle_ops.md) for full procedures.

Runbook-level rules:

- replace adapters only through approved maintenance windows
- reset cursors only for a specific template/feed pair and never as bulk cleanup
- for reporter incidents, pause first, rotate second, clear only what is necessary, then repost with review

## Fee Withdrawal

Before `withdrawFees(templateId, amount)`:

- verify the treasury address
- verify amount is within accounting expectations
- verify no incident is underway that requires freezing fee movement

After withdrawal:

- fee vault and reserve totals decreased correctly
- transfer destination was the approved treasury

## Upgrade and Module Maintenance

Use:

- [./.governance.md](./.governance.md)
- [./.module_release.md](./.module_release.md)

Runbook rules:

- pause before upgrade by default
- do not treat root-owned selectors as module-routed selectors
- verify delegated selector wiring only against the delegated manifest

## Critical Alerts

Treat these as high-severity or critical:

- `YieldRouterDisabled`
- `YieldEmergencyWithdrawn`
- `EmergencyRecoveredBalanceReassigned`
- `OracleCursorReset`
- `RollingHalted`
- `ModuleRegistered`
- `ModuleRevoked`
- `SelectorModuleSet`
- UUPS upgrade execution
- reporter rotation and clear events

## Explicit “Do Not Do This”

Do not:

- unpause while recovery is pending
- replace router with outstanding routed principal
- rewire root-owned selectors through module governance
- clear reporter data without an incident record
- bulk-reset oracle cursors
- retry rolling execution endlessly after a halt without diagnosis

## Final Rule

When in doubt, the safe order is:

**pause -> inspect operator views -> identify exact failed state -> execute one approved recovery path -> validate -> only then consider unpause.**
